# DNA · 视频口播风格蒸馏仓库

把 **skill**、**UP 主原文案（逐字稿）**、**对应的 5 个蒸馏文件** 放在一起，供多人审核、多端共享与长期维护。

- 仓库当前为 **private**；审核者需由仓库所有者邀请。
- 用途：写作风格研究、Agent workflow 审核、内容流水线复刻的素材管理。
- 不用于冒充原作者、不搬运原文观点与内容，详见 `NOTICE.md`。

## 数据口径（v1.2.0）

- 情绪词表剔除泛用副词「最」：单独 224 次命中、占原统计 47.8%，密度由 11.16 降到 **6.6/千字**。
- **单支爆款不得当基准**：79 万播放＝频道中位数 52,059 的 **15.2 倍**且热点强度 high，事件热度与写法贡献无法分离，标为离群点并降权。
- 改逐支相关：对 `log10(播放)` 与各指标算 Pearson r，同时给出「剔除离群点」后的 r（n=7 / n=6，**均不具统计显著性**）。只有两口径都正向的**时间压迫、权威机构提及、认知承诺**写成硬约束，其余只作诊断、不设配额。
- `play_norm` 与 `hot_intensity`（high / medium / low）为必填元数据；当前热点强度为人工估计，待编辑确认。
- 规则必须能被自家数据验证：已删除与数据冲突的「数字每 5 分钟 ≤6」硬阈值，并把「1:16 报栏目名」降级为单支特征（7 支中仅 1 支）。
- 新增「动机判断可证伪」与「续集选题处理」，见 `SKILL.md` 6.4 / 6.5。

## 维护规范

### 新增一个 UP 主

1. 在 `02-creators/` 下新建 `<UP主名>/`，复制 `财富咖啡/` 的两个子目录结构。
2. 把逐字稿放进 `01-文案/raw/`，建议命名 `YYYY-MM-DD_标题_BV号.txt` 与同名 `.srt`；只放 `.txt` 也可。
3. 填 `01-文案/_meta.md`：标题、日期、时长、播放、`play_norm`、`hot_intensity`、信息截至日期。
4. 按 `01-skill/SKILL.md` 的 Step 1–5 蒸馏，把 5 个文件写进 `02-蒸馏/`；量化证据放 `evidence/`。
5. 更新 `02-creators/README.md` 的 UP 主清单与根 `README.md` 的「当前内容」表。

### 命名与素材

- 一个 UP 主一个文件夹，互不干扰；新增时不要改已有 UP 主的目录。
- 逐字稿与蒸馏文件都随仓库版本化，便于多端同步与 diff 审核。
- 完整蒸馏门槛 **≥20 支**且覆盖不同时期 / 题材 / 热点强度；不足时 skill 必须先与用户确认是否接受低置信度预览版。
- 转写有专名误识，引用原文需标注，不作为事实依据。

## 审核重点

- `SKILL.md` Step 1 语料数量确认是否为硬性步骤；Step 6 是否完整保留 5 份产物 + 5 篇原文 few-shot。
- 统计口径是否真的剔除了离群点与污染词；「可作约束」的指标是否两个 r 口径都正。
- 蒸馏文件里的每条规则能否在 `evidence/` 里找到对应数据；自检表字段名是否与统计表一致。
- 动机判断是否都带假设措辞、信息截至日期与证伪条件；续集是否回扣前作并认账。
- 所有结论是否标注为相关性而非因果、以及低置信度边界。

## 边界

- 仓库为 private，仅供受邀审核者访问；请勿整体公开或二次分发逐字稿。
- 蒸馏结论是相关性不是因果；播放量还受热点热度、发布时点、推荐池影响。
- 只复刻写法，不冒充原作者、不搬运原文观点与内容；公开发布时建议标注风格参考写作。
